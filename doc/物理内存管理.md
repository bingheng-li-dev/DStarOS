# 物理内存管理
## 相关结构说明
一个物理页（4096B）由一个`pframe_t`描述。
```C
struct phyframe
{
    uint16_t nsize;     /* The size of this block which free or to be used. */
    uint16_t reference; /* Amount of vir page used. */
    bool canBeAlloc;    /* True:this frame is the head of a free block and can be alloc;false:this frame is in usage or it is not the head of a block. */
    virAddr_t va;       /* Used for pra. */
    struct list_head list_linker_inFreeList;
    struct list_head list_linker_inFreeAList;
    struct list_head list_linker_inClockList;
};
typedef struct phyframe pframe_t;
```
`struct list_head`是内核链表结点项。
`list_linker_inFreeList`和`list_linker_inFreeAList`分别对应该物理页在空闲物理内存链表`fslist_t FreeList`、`fslist_t FreeAList`中的结点项。
```C
struct freeSpaceList /* Record the addr of the free list from small to large. */
{
    struct list_head list_linker;
    uint16_t fnsize; /* PGSIZE times */
};
typedef struct freeSpaceList fslist_t;
```
`FreeList`将空闲内存块按由小到大的顺序排列，用于best fit方法管理物理页分配，`FreeAList`将空闲内存块按地址由小到大的顺序排列，用于回收内存时判断是否需要合并。
`FreeList`，`FreeAList`链表都有头结点，头结点记录总的空闲物理页的数量（`fnsize`）。
被分配的`pframe_t`中的`nsize`记录此物理块的大小（含有几个连续物理页），用于`kfree`函数回收。

## 空闲物理页分配

空闲物理页的分配采用 **最佳适应（best fit）** 策略，允许一次性分配一段**连续**的物理页。涉及的函数有：
>    * `pframe_t *alloc(uint16_t nsize)`         —— 对外的分配接口，`nsize` 为需要的连续物理页数量
>    * `pframe_t *alloc_page(void)`              —— `alloc(1)` 的便捷封装，分配单个物理页
>    * `static pframe_t *deleteAndReinsert(uint16_t nsize)` —— 真正的分配逻辑，挂在 `BFallocator.bffa_deleteAndReinsert` 上

### 总体流程

`alloc` 是分配的入口，它在 `deleteAndReinsert` 的基础上完成额外的检查、清零和记账工作，调用链为：

```
alloc(nsize)
   └── BFallocator.bffa_deleteAndReinsert(nsize)  ==  deleteAndReinsert(nsize)
```

1. **容量预检**：若请求的 `nsize` 大于 `FreeList.fnsize`（当前剩余的空闲物理页总数），说明物理内存已经不足以满足本次请求，此时本应触发页面置换算法（page replacement）换出部分页面，但该算法尚未实现，因此直接 `goto f1` 返回 `NULL`。
2. **取块**：通过 `deleteAndReinsert(nsize)` 在 `FreeList` 中按最佳适应找到合适的空闲块。
   - 这里用一个 `while(1)` 循环包裹调用，是为将来的页面置换预留的重试逻辑：当 `ret == NULL` 且请求只有 1 页（`nsize == 1`）时，理应换出一页后再次尝试（`vmm_swapOut` 当前被注释掉）。只要拿到结果（`ret != NULL`）或请求大于 1 页（`nsize > 1`，无法靠换出单页满足），就跳出循环。
3. **分配成功后的处理**（`ret != NULL`）：
   - 把这段连续物理页中每个 `pframe_t` 的 `canBeAlloc` 置 `0`，标记为“已占用 / 非空闲块头”。
   - 将这段物理内存按字节清零（出于安全考虑，避免泄露上一个使用者残留的数据）。
   - 把块头帧的 `ret->nsize` 记为本次分配的大小 `nsize`，供日后 `dealloc` 回收时知道该释放多少页。
4. **分配失败**（`ret == NULL`）：由于页面置换尚未实现，目前只能 `panic`。

### deleteAndReinsert：最佳适应与分裂

`FreeList` 中的空闲块**按 `nsize` 由小到大排列**，因此从表头开始顺序查找、命中的**第一个** `nsize >= 请求大小` 的块即为最佳适应块（满足需求且浪费最少）。

```
FreeList:  [2页] -> [5页] -> [9页] -> ...   （按块大小升序）
                     ^
请求 nsize=4，第一个 >=4 的块是 5 页块，即最佳适应块
```

找到目标块 `ret` 后：

1. **摘除**：将 `ret` 同时从 `FreeList` 和 `FreeAList` 中删除（`list_del` 两个链接结点）。
2. **是否需要分裂**：
   - 若 `ret->nsize == nsize`（块大小恰好等于请求），无需分裂，整块取走即可。
   - 若 `ret->nsize > nsize`（块比请求大），则把块**分裂**为两段：前 `nsize` 页交付给调用者，剩余 `ret->nsize - nsize` 页作为一个新的空闲块重新插回两个链表。
     - 剩余块的块头帧为 `reinsertFrame = ret + nsize`（即跳过被分配出去的那部分），其 `nsize` 更新为剩余页数。
     - **重新插入 `FreeList`**：因 `FreeList` 按大小升序，需遍历找到第一个 `nsize >= reinsertFrame->nsize` 的位置，用 `list_add_tail` 插到其前面以保持有序；若 `reinsertFrame` 比表中所有块都大，则追加到表尾。
     - **重新插入 `FreeAList`**：因 `reinsertFrame` 的地址必定落在原 `ret` 的位置上（只是起始地址后移了 `nsize` 页），它在地址序中的相对位置不变，所以直接借助 `ret` 被删除前留下的 `(ret->list_linker_inFreeAList).prev` 把剩余块插回**原来的地址位置**即可，无需重新遍历查找。
   - 特殊情况：删除目标块后若 `FreeList` 只剩头结点（`next == &FreeList.list_linker`，即表为空），则把剩余块直接挂到表头（`goto f1`），跳过有序插入的遍历。
3. **记账**：从 `FreeList.fnsize` 与 `FreeAList.fnsize` 中各减去本次分配出去的 `nsize` 页。

> 说明：`FreeList`（按大小排序）服务于分配时的最佳适应查找，`FreeAList`（按地址排序）服务于回收时的相邻块合并判断（见后文“小段内存管理 / 回收”相关逻辑）。两条链表中的同一个空闲块由同一个 `pframe_t` 的两个不同链接结点（`list_linker_inFreeList`、`list_linker_inFreeAList`）分别串接，因此分配 / 回收时必须同步维护两条链表。

### 地址与帧的换算

分配返回的是块头帧的 `pframe_t *`，需要时通过 `pmm.h` 中的内联换算函数在 `pframe_t *`、`ppn`（物理页号）、`pa`（物理地址）三者间转换，例如 `alloc` 内部清零时就用 `convert_pframe2pa(ret)` 取得起始物理地址：

| 函数 | 含义 |
|---|---|
| `convert_pframe2ppn(frame)` | 帧指针 → 物理页号 |
| `convert_pframe2pa(frame)`  | 帧指针 → 物理地址 |
| `convert_ppn2pframe(ppn)`   | 物理页号 → 帧指针 |
| `convert_pa2pframe_flr(pa)` | 物理地址（向下取整）→ 帧指针 |

## 小段内存管理
在pmm.c中有3个相关函数：
>    * `static void initMicroPhysicalMemoryPool(void)`
>    * `void *microAlloc(uint64_t size)`
>    * `bool microDemalloc(void *ptr)`

它们分别用于：
    初始化内存池：在物理内存初始化完成的时候调用，动态分配2个物理页共8KB用于小段内存分配。
    分配小段内存：根据传入的参数size的大小决定
    释放小段内存
